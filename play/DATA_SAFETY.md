# Spends — Play Console "Data safety" answers

Fill this in Play Console → **Policy → App content → Data safety**. Below are the recommended answers
with the reasoning, so you can defend them if asked. Spends is local-first and sends **nothing to the
developer**, ever. User data leaves the phone in exactly one place: the user's **own** Google Drive, if
they switch backup on. One further feature contacts a third party — **AI currency conversion** — but what
it transmits contains **no user data at all** (see §1a); that distinction is the whole basis for the
"Shared: No" answers below, so read it before filling the form.

## Section 1 — Data collection and security

**Does your app collect or share any of the required user data types?**
→ **Answer: Yes**, for the **optional Google Drive backup** only — and **"shared": No**.

Rationale (Play's definition of *collect* = transmitted off the device to you or a third party; *share*
= transferred to a third party):
- SMS content is parsed **on-device** and is **never transmitted anywhere**, in any configuration.
- All transactions/financial data live in an on-device database.
- The **optional** Google Drive backup writes to the **user's own** Google account (a "Spends Backup"
  folder the app creates; `drive.file` scope — the app can only access files it created, never the rest of
  the user's Drive). Per Google's Data safety guidance, transferring data to a user-controlled cloud account
  that the developer cannot access is **not** developer "collection" or "sharing." The developer never
  receives this data. It is still declared, as **collected / not shared / optional**, because the data does
  leave the device.
- No analytics/ads/third-party SDKs collect anything.
- **No user data is shared with any third party** — including by the AI currency conversion feature. See
  §1a, which is the answer to give if a reviewer asks why an app that contacts an AI provider declares no
  sharing. (The unrelated v1.56.0–v1.64.0 AI helper, sideload-only and never on Play, *did* send masked
  message extracts and spending aggregates to Groq. It no longer exists, and the key it used is erased the
  next time a user opens Spends.)

## Section 1a — AI currency conversion, and why "Shared" is still No

**The feature.** Off by default. The user must switch it on *and* paste their own API key (Anthropic,
OpenAI or Groq — their choice). Until both are done the app makes no AI request at all.

**What is transmitted.** One generic question with no user data in it:

> `How many INR is 1 MYR right now?`

That is the entire payload, plus a fixed system prompt describing the JSON to reply with. **No amount, no
merchant, no account or card number, no message text, no timestamp, no device or user identifier.** The
provider is asked what a currency is worth; the conversion arithmetic then happens on-device. Answers are
cached for six hours, so a day of bank alerts typically costs one request.

**Why that is not "collection" or "sharing" under Play's definitions.** Play defines both in terms of
**user data** being transmitted off the device. An exchange-rate question is not user data: it is
identical for every user in the world holding those two currencies, and it reveals nothing about this
user's transactions, identity or device. Nothing the provider receives could be joined back to a person.

**The API key.** It is the user's own credential for a service *they* chose and signed up to, sent to that
service to authenticate their own request — structurally the same as the Google OAuth token used for their
own Drive backup. It is generated by the provider, not derived from the user's data; it is encrypted at
rest on the device, excluded from backups, and never sent anywhere except the provider selected.

**If a reviewer pushes back**, the honest and sufficient answer is the payload above: the app can be
observed making the request, and the request contains no user data. The user can also pin a fixed exchange
rate in Settings, in which case the feature makes no network call whatsoever.

**Is all of the user data collected by your app encrypted in transit?**
→ **Yes.** (Both network paths use HTTPS: the optional Drive backup, and the optional AI rate question —
which carries no user data in any case. On-device data is not in transit.)

**Do you provide a way for users to request that their data be deleted?**
→ **Yes.** Users delete entries in-app (Trash), clear app data / uninstall to wipe everything on-device,
and delete the Drive backup from within Spends or from Google Drive. (No server-side account exists.)

## Key facts to keep consistent everywhere (listing, policy, this form)
- SMS is read **on-device**, is **optional**, and the app **works without it**. Message content **never**
  leaves the device.
- No ads, no analytics, **no third-party sharing of user data at all**.
- Backup, if used, goes to the **user's own** Google Drive; the developer has no access.
- AI currency conversion, if used, sends **only an exchange-rate question** to a provider the user chose
  with a key they supplied — no amounts, no merchants, no message content (§1a).
- Data deletion is available (in-app Trash, clear data/uninstall, delete Drive backup, remove the API key).
- Encryption in transit: yes — both network paths (Drive backup, AI rate question) use HTTPS.
